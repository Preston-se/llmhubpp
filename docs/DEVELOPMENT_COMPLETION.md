# 用户功能、Wiki 与 MCP 的完成条件

本文列出本插件的开发完成要求。接入 Agent 时，保留用户配置、原索引、已安装模型和自定义能力。

## 新增或改变用户功能

同一任务更新 resources/help/feature-map.json、对应用户 Wiki，以及可用的 MCP 配置/诊断入口。若属于内容读取、附件上传、转换、索引重建、脚本或工作流执行，明确登记非配置执行边界，不把配置授权扩大为内容执行授权。

Wiki 面向用户：说明适用任务、实际入口、操作步骤、推荐条件及倾向影响、验证方法和失败处理。关键流程提供随包 SVG 与替代文字，图示放在相关步骤附近；字段细节留在高级附录。用真实 Obsidian 检查深浅主题、窄窗、返回/章节/设置跳转，不能用浏览器静态页替代宿主验证。

新增设置页必须有显式功能条目。任意新行为无法全靠 CI 识别，实施者和评审必须检查是否改变了用户可见流程及权限/费用/外发边界。

## 新增、删除或修改配置

结构类型与 Safe Guard 默认值决定 schema；documentationCatalog.ts 与显式 documentationPaths.ts 决定语义覆盖。根字段、嵌套字段及集合通配路径均需同步，系统只读项也要解释原因，秘密保持只写/脱敏。删除或改名清理孤儿条目，旧 MCP 工具/参数和配置包需有兼容策略。

说明标题、用途、单位、生效方式、推荐值及条件、不同倾向影响、依赖、风险、验证与失败。默认建议取实际源码；不能复制某个用户的配置当产品默认。风险权限扩张、可执行入口、凭据保存和保护变化需核对方向，外部不能伪造系统验证结果。

MCP 元数据同时维护输入/输出 schema、注解、可恢复错误、惰性字段资源及 Agent 引导。状态不隐式联网，不读取全库向量；保存、运行时应用、外部验证与真实任务质量分开报告。纯探测不保存、不推理、不扫描或启动任意命令。

## 验证与候选交付

1. 行为变化先写可观察的失败测试，再实现；不为低影响文案/样式写镜像断言。
2. npm run generate:configuration 生成字段参考、机器文档、协作引导与帮助锚点。
3. npm run check:docs-mcp 检查公开路径双向覆盖、示例/推荐、Wiki 链接/锚点/图片、功能与设置页映射，以及真实工具结果消费者合同；隔离副本负向测试必须通过。
4. 完成适合变更的类型、lint、全量回归、原生宿主验证及 npm run test:package；build/build:llmhubpp 与 CI 使用相同文档/MCP 门槛。
5. 核验实际用户配置、原索引与自定义文件未被本轮工具写入；保留源码备份、差异、日志及独立候选哈希。未经用户要求不自动安装候选、提交、推送、打 tag 或清理 worktree。

交接区分源码证据、合成接口、原生宿主结果、真实第三方服务/Agent 未验证项。自动化测试不证明任意模型遵从引导，也不代表用户已验收或真实账单一致。
