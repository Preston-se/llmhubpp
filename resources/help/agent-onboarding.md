# 协作配置引导

请用户在插件本地填写密钥或密码；Agent 只读取 configured/missing，不让用户粘贴秘密到聊天。

- 关键选择按“控制什么、推荐起点、适用原因、不同倾向影响、何时再调”说明，不只抛字段名。
- 先给保留项、新建项、原因、影响和验证的短提案；已有范围授权可直接 preview/apply，普通字段不重复询问。
- 先 status 与定向 read/describe；候选服务可显式 probe，受管服务用 check。列表成功不等于生成、视觉或嵌入质量通过。
- 配置不授权转换、同步、重建索引、推理、下载、执行脚本或扩大权限。
- 有可用候选但当前选择失效时，先 repair，不自动新建同名服务。

## 核心选择

![协作配置先问用途、模型位置、隐私、预算和资料范围，再准备短提案](images/agent-onboarding.svg)

### 主要用来做什么？
用途决定是否需要知识库、视觉模型或自动化；先完成一个常见任务，再展开高级项。

- 普通聊天：先配聊天模型即可。
- 资料阅读与检索：还需选择资料范围和嵌入服务。
- 图片与复杂资料：要验证视觉或文字解析能力及图片外发。
- 工作流与自动化：工具权限和执行任务需要单独授权。

### 使用哪里的模型或已有服务？
本机/局域网需已有运行服务；云端需要账号与外发许可。插件不会自动安装或下载模型。

- 本机已有模型：可减少资料出站，能力和速度取决于本机。
- 局域网服务：需明确服务地址及是否属于受信本地 origin。
- 云端 API：资料会发送给服务商，需核对费用与隐私。
- 按任务混用：区分本地与云端用途，不静默切换服务。
- 沿用已有配置：先诊断和验证，保留模型列表与当前值。

### 资料允许怎样发送和修改？
先说明资料会去哪里。只读限制库写入，不等于禁止外发；文字脱敏不能可靠处理图片或 PDF。

- 仅本地发送：远端调用会被拦截，局域网需明确加入受信 origin。
- 远端发送前确认：便于核对正文，二进制不能按文字预检。
- 规则脱敏：需先测试规则，不能保证去除所有秘密。
- 沿用原发送方式：不改变外发正文，需用户理解所选服务。

### 是否付费，以及本月预算和已有支出？
硬预算只覆盖受管 HTTP；需实际人民币费率与已有支出。未知费率会拦截，CLI、MCP 和实时语音另计。

- 先用本地或免费服务：不自动启用硬预算，服务商收费仍需另核对。
- 付费并设上限：先填预算、已有支出和费率，预留输出费用。
- 先解释再决定：保留现有设置，不把未知费用当作免费。

### 要处理哪些资料，是否已有索引？
明确格式、目录和规模，优先保留原件与旧索引；转换、同步和重建是独立执行任务。

- 沿用已有索引：先查可读性和兼容性，不重新迁移。
- 新的文字资料：先小范围验证解析与检索，再扩大范围。
- PDF、图片或复杂文件：先看解析质量，扫描件可能需要另行 OCR。
- 暂不使用资料库：普通聊天可先完成，稍后再补知识库。

## 当前建议
### 默认只读保护
控制：默认限制写入等动作；关闭会扩大能力，必须符合用户授权。

推荐起点：true

适用：以资料阅读、检索和问答为主，尚未明确授权写入任务时。

原因：先验证可用性和资料范围，再按真实任务开放写能力。

- 开启时按现有权限边界限制写入，适合资料阅读起点。
- 关闭可能扩大写能力，只在用户明确需要并授权时调整。

详解：[查看参数说明](help:configuration-fields#safeguard-defaultreadonlyenabled)

### 输出 Token 上限
控制：过低会截断，过高需要更多预算预留。

推荐起点：4096

适用：首次配置且用户尚无其他偏好时，先说明当前建议及保护覆盖范围，再按预算和隐私意愿选择。

原因：建议起点来自运行时默认；开启硬预算前补全费率和本月已有支出，不能保证整机总费用。

- 较高上限允许长回答，但需要更多预算预留。
- 较低上限节省预留，可能使回答被截断。

详解：[查看参数说明](help:configuration-fields#settings-requestcontrols-maxoutputtokens)

### 工具回合上限
控制：限制连续回合，避免长循环消耗预算。

推荐起点：20

适用：首次配置且用户尚无其他偏好时，先说明当前建议及保护覆盖范围，再按预算和隐私意愿选择。

原因：建议起点来自运行时默认；开启硬预算前补全费率和本月已有支出，不能保证整机总费用。

- 更多回合可能完成复杂任务，同时增加时间和费用。
- 较少回合减少循环开销，可能需要用户分段推进任务。

详解：[查看参数说明](help:configuration-fields#settings-requestcontrols-maxtoolrounds)

### 候选证据数量
控制：多一些可能补足证据，也增加噪声、上下文和费用。

推荐起点：5

适用：新建普通文本知识库、缺少实测数据时，先使用当前源码默认起点；已有用户值不覆盖。

原因：先建立可验证基线，再用自己的问题检查遗漏、噪声和上下文开销。

- 更多候选有助于补足分散证据，也可能混入不相关片段。
- 更少候选可减少上下文和费用，但可能遗漏需要的证据。

详解：[查看参数说明](help:configuration-fields#workspace-ragsettings-entry-topk)

### 文本块长度
控制：按 JS 字符分块，大块上下文多，小块定位细但块数多。

推荐起点：500

适用：新建普通文本知识库、缺少实测数据时，先使用当前源码默认起点；已有用户值不覆盖。

原因：先建立可验证基线，再用自己的问题检查遗漏、噪声和上下文开销。

- 较大文本块保留上下文，但定位更粗、单段负载更大。
- 较小文本块定位更细，但向量和检索块数可能增加。

详解：[查看参数说明](help:configuration-fields#workspace-ragsettings-entry-chunksize)

### 自动更新索引
控制：保存后后台更新，可能调用嵌入；关闭仍可手动更新。

推荐起点：true

适用：新建内部可写索引、嵌入服务已配置且允许后台调用时；旧配置保留用户选择。

原因：让编辑后的笔记及时进入检索；有费用或离线要求时可关闭并手动更新。

- 开启后，匹配范围的保存会排队调用嵌入服务。
- 关闭后继续编辑不会自动重建，但仍可手动更新单篇。

详解：[查看参数说明](help:configuration-fields#workspace-ragsettings-entry-autoupdateindex)
